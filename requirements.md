# Requirements Specification: Showphan (Version 1)

This document formalizes the functional requirements, user stories with testable acceptance criteria, non-functional requirements, business rules, and constraints for Version 1 of Showphan.

---

## 1. User Stories & Acceptance Criteria

### US-1: Developer Authentication & First-Time Onboarding
**As a** Developer,  
**I want to** sign in using my public GitHub account,  
**so that** I can securely manage my portfolio without creating another password.  
**Priority:** Essential

#### Acceptance Criteria:
- **AC-1.1:** Given a visitor on any page, when they click "Sign in with GitHub", then they are redirected to GitHub's OAuth consent screen requesting only public profile permissions (`read:user`).
- **AC-1.2:** Given a user approving GitHub OAuth for the first time, when they return to Showphan, then a user account is created with `github_id`, an immutable `slug` derived from their current GitHub username, their GitHub avatar URL, and their display name, followed by redirection to the welcome step.
- **AC-1.3:** Given a user denying GitHub authorization or if OAuth fails, when they return to Showphan, then no account or session is created, and they are redirected to the landing page with a clear, non-punitive notification (`"Sign in was cancelled, you can try again."`).
- **AC-1.4:** Given an existing developer signing in, when authentication completes, then they are redirected directly to `/dashboard`.
- **AC-1.5:** Given a signed-in developer, when they click "Sign out", then their session cookie is invalidated and they are redirected to the landing page.

---

### US-2: Project Creation & Auto-Drafting
**As a** Developer,  
**I want to** draft a new project with real-time saving and instant preview,  
**so that** I never lose my work and can see exactly how it will look before publishing.  
**Priority:** Essential

#### Acceptance Criteria:
- **AC-2.1:** Given a signed-in developer on `/dashboard/new`, when they enter a project title, then a draft is created with status `DRAFT` and a unique slug per user.
- **AC-2.2:** Given an active project form, when changes are made to title, summary, description, links, role, or learnings, then the draft autosaves in the background with a status indicator (`"Saved just now"`).
- **AC-2.3:** Given the project creation form on desktop, when typing or updating fields, then the live card preview and project page preview on the right update synchronously.
- **AC-2.4:** Given a mobile device, when editing a project, then tabs for "Edit" and "Preview" are available, with the "Publish" button pinned at the viewport bottom.
- **AC-2.5:** Given a developer with 30 existing projects, when viewing the dashboard, then the "Add project" button is disabled with an explanatory tooltip (`"Maximum limit of 30 projects reached"`).

---

### US-3: Cover Image Upload & Processing
**As a** Developer,  
**I want to** upload and crop a single 16:9 cover image for my project,  
**so that** my project looks sharp and professional across cards and detail pages.  
**Priority:** Essential

#### Acceptance Criteria:
- **AC-3.1:** Given an image file selection (drag-and-drop or file picker), when the file is not JPG, PNG, or WebP, then it is rejected immediately with an error message.
- **AC-3.2:** Given a valid image file, when uploaded in the browser, then it is constrained to a 16:9 crop frame and resized to a maximum width of 1600px, converted to WebP format, and verified to be ≤ 1MB.
- **AC-3.3:** Given an image narrower than 1000px, when selected, then a non-blocking warning is displayed recommending higher resolution for crisp readability.
- **AC-3.4:** Given a validated client-side image, when uploaded, then the browser uploads directly to Cloudflare R2 using a short-lived presigned upload URL generated by the server.
- **AC-3.5:** Given a project with an existing cover image, when a new image is saved or the project is deleted, then the previous image key is purged from Cloudflare R2.

---

### US-4: Project Publishing & Quality Gate Enforcement
**As a** Platform,  
**I want to** enforce complete project details before publishing,  
**so that** no low-quality or half-baked projects are visible on Showphan.  
**Priority:** Essential

#### Acceptance Criteria:
- **AC-4.1:** Given a draft project, when the developer views the publish panel, then a 5-item checklist is displayed indicating completion progress (e.g., "4 of 5 complete").
- **AC-4.2:** Given any of the following missing fields:
  1. Title
  2. Summary (plain text, ≤ 140 chars)
  3. Cover image
  4. At least one technology tag
  5. At least one of Live URL or Repository URL  
  When evaluated, then the "Publish" button remains disabled and explicitly lists the missing items.
- **AC-4.3:** Given all 5 checklist items fulfilled, when the developer clicks "Publish", then the project status transitions to `PUBLISHED`, and a success modal displays the public project link, a copy button, and a share preview.
- **AC-4.4:** Given a published project, when the developer clicks "Unpublish", then status reverts to `DRAFT`, removing it from the public profile and returning 404 to visitors.

---

### US-5: Public Profile View
**As a** Visitor,  
**I want to** view a developer's profile via their custom link (`/<slug>`),  
**so that** I can evaluate their skills, bio, and projects on a single page.  
**Priority:** Essential

#### Acceptance Criteria:
- **AC-5.1:** Given a visitor navigating to `/<slug>`, when the profile exists, then the page renders server-side displaying the developer's GitHub avatar, display name, bio (≤ 160 chars), featured projects (up to 6), and the standard project grid.
- **AC-5.2:** Given a profile page, when loaded by a visitor, then only projects with status `PUBLISHED` are rendered. Drafts are omitted completely.
- **AC-5.3:** Given a developer with 0 published projects, when a visitor navigates to `/<slug>`, then a neutral empty state is shown and the page carries `noindex` robots meta tags.
- **AC-5.4:** Given the profile owner viewing their own profile while signed in, then a persistent top action bar appears with "Dashboard" and "Copy profile link" actions.
- **AC-5.5:** Given a visitor clicking "Copy profile link", then the canonical profile URL is copied to the clipboard with an ephemeral toast confirmation.

---

### US-6: Standalone Project Page
**As a** Visitor,  
**I want to** view the full details of a specific project (`/<slug>/<project-slug>`),  
**so that** I can review the tech stack, problem description, role, and try the live demo or inspect the source.  
**Priority:** Essential

#### Acceptance Criteria:
- **AC-6.1:** Given a published project URL, when loaded, then the full-size 16:9 cover image, title, summary, action buttons (Live Demo, Source Code, Copy Link), tech stack badges with icons, markdown description, role, and learnings are rendered.
- **AC-6.2:** Given a visitor clicking the cover image, then a full-resolution lightbox viewer opens with keyboard Escape dismissal.
- **AC-6.3:** Given a project where the source repository is private or unprovided, when rendered, then the "Source Code" button is replaced by a badge reading `"Source code is private"`.
- **AC-6.4:** Given external links (Live URL, Repo URL), when clicked, then they open in a new tab with attributes `rel="ugc nofollow noopener noreferrer"`.
- **AC-6.5:** Given a project description containing Markdown, when rendered, then raw HTML tags, `<script>` tags, and embedded markdown images (`![]()`) are stripped or sanitized.
- **AC-6.6:** Given a draft project URL accessed by an unauthenticated visitor, when requested, then an HTTP 404 Not Found response is returned.

---

### US-7: Project Management Dashboard
**As a** Developer,  
**I want to** view and manage all my projects in a unified dashboard (`/dashboard`),  
**so that** I can track project statuses, reorder entries, and perform quick actions.  
**Priority:** Essential

#### Acceptance Criteria:
- **AC-7.1:** Given an authenticated developer on `/dashboard`, when rendered, then projects are organized in rows with thumbnail, title, status badge (`Draft` / `Published`), feature toggle, and relative edited timestamp (`"Edited 2 hours ago"`).
- **AC-7.2:** Given the dashboard project list, when filtered via tabs, then developers can switch between "All", "Published", and "Drafts".
- **AC-7.3:** Given projects on the dashboard, when the developer drags the row handle or uses keyboard "Move up" / "Move down" controls, then project display positions update and persist.
- **AC-7.4:** Given a project deletion request, when confirmed through the modal stating that the project and cover image will be permanently removed, then the database record and R2 image are deleted with no undo.

---

### US-8: Featured Projects Management
**As a** Developer,  
**I want to** mark up to 6 projects as "Featured",  
**so that** they appear prominently in larger cards at the top of my public profile.  
**Priority:** Important

#### Acceptance Criteria:
- **AC-8.1:** Given a project row on the dashboard, when toggling the "Featured" switch on, then `is_featured` becomes true and the project displays in the featured section.
- **AC-8.2:** Given a developer with 6 projects already marked as featured, when attempting to toggle a 7th project, then the toggle remains disabled with an explanatory tooltip (`"Maximum of 6 featured projects allowed"`).
- **AC-8.3:** Given a profile with 0 featured projects, when viewed, then the featured projects section is cleanly omitted from the layout.

---

### US-9: GitHub Public Repository Import
**As a** Developer,  
**I want to** import metadata from one of my public GitHub repositories,  
**so that** I can prefill my project details in one click instead of typing everything manually.  
**Priority:** Important

#### Acceptance Criteria:
- **AC-9.1:** Given the project creation form, when the developer clicks "Import from GitHub", then a modal displays a searchable list of their public repositories fetched via the server-side GitHub API.
- **AC-9.2:** Given a selected repository, when confirmed, then the form auto-populates:
  - Title (repository name, formatted)
  - Summary / Description (repository description)
  - Repository URL (`html_url`)
  - Live URL (repository `homepage`, if set)
  - Technologies (mapped from repository topics and primary language)
- **AC-9.3:** Given imported data, when populated, then existing form fields are not overwritten without explicit user confirmation.

---

### US-10: Developer Profile Settings & Privacy Controls
**As a** Developer,  
**I want to** update my display name, bio, and search engine visibility settings,  
**so that** I control how my identity and portfolio appear to the world.  
**Priority:** Important

#### Acceptance Criteria:
- **AC-10.1:** Given `/settings`, when updating display name or bio (≤ 160 characters), then changes save and reflect immediately across public profile views.
- **AC-10.2:** Given `/settings`, when clicking "Refresh from GitHub", then the latest GitHub avatar URL is re-fetched and saved.
- **AC-10.3:** Given the profile slug on `/settings`, when viewed, then it is displayed as read-only with a message explaining that changing it would break existing shared links.
- **AC-10.4:** Given the switch "Show my profile in search engines" (default ON), when turned OFF, then the public profile and all its project pages inject `noindex, nofollow` headers and meta tags and are removed from `sitemap.xml`.
- **AC-10.5:** Given an account deletion request on `/settings`, when the developer types their username to confirm, then all projects, cover images in R2, sessions, and user records are permanently deleted.

---

### US-11: Theme Customization
**As a** User (Developer or Visitor),  
**I want to** choose between System, Light, and Dark themes with Dark as default,  
**so that** viewing portfolios is comfortable in any ambient lighting condition.  
**Priority:** Important

#### Acceptance Criteria:
- **AC-11.1:** Given a first-time visitor, when loading any page, then the Dark theme is rendered by default unless the client's OS explicitly prefers light mode and System is active.
- **AC-11.2:** Given the theme toggle in the header, when a user selects "Light", "Dark", or "System", then the theme applies instantly without page reload and persists in local storage/cookies.
- **AC-11.3:** Given theme switching, then surfaces, typography, cards, and borders shift smoothly between Zinc-950/Zinc-900 (Dark) and Zinc-50/White (Light) while Amber accent (#F59E0B) remains visually prominent.

---

### US-12: Social Sharing & Link Previews
**As a** Developer,  
**I want to** share my profile and project links on LinkedIn, Twitter, and WhatsApp,  
**so that** recipients see high-fidelity cards with images, summaries, and titles.  
**Priority:** Important

#### Acceptance Criteria:
- **AC-12.1:** Given a shared project link, when scraped by crawlers, then Open Graph and Twitter Card meta tags output the project title, 140-char summary, canonical URL, and the 16:9 WebP cover image.
- **AC-12.2:** Given a shared profile link, when scraped, then Open Graph outputs the developer's name, bio, and the cover image of their first featured project (or fallback Showphan branded banner).
- **AC-12.3:** Given the landing page link, when scraped, then Open Graph outputs `"Showphan: Developer Portfolio Platform"` and the platform banner.

## 2. Non-Functional Requirements (NFRs)

| ID | Category | Metric / Target | Verification Method |
| :--- | :--- | :--- | :--- |
| **NFR-1** | **Performance (LCP)** | Largest Contentful Paint ≤ **2.5s** on simulated 4G mobile devices. | Lighthouse CI & Chrome DevTools |
| **NFR-2** | **Performance (Latency)** | Public profile & project page Server-Side response time ≤ **200ms** (via ISR/Edge caching). | Vercel Analytics / Server Timers |
| **NFR-3** | **Storage & Size** | Cover images must be WebP format, ≤ **1600px** width, and ≤ **1.0 MB** payload. | Server-side upload validation schema |
| **NFR-4** | **Accessibility** | All text and UI components achieve **WCAG 2.1 AA** contrast ratios (≥ 4.5:1 for normal text). | Axe DevTools / Lighthouse Accessibility ≥ 95 |
| **NFR-5** | **Touch Targets** | Interactive elements (buttons, links, toggles) have minimum touch targets of **44 × 44 px** on mobile. | CSS inspection & automated viewport audits |
| **NFR-6** | **Security (Sanitization)** | Markdown rendering must strip 100% of raw `<script>`, `<iframe>`, `<object>`, and `<img>` tags. | Automated unit tests with `rehype-sanitize` |
| **NFR-7** | **Security (CSP & Headers)** | Content-Security-Policy, HSTS, X-Content-Type-Options, and Referrer-Policy headers enforced. | Securityheaders.com audit |
| **NFR-8** | **SEO (Clean URLs)** | Lowercase, hyphenated slugs only. No trailing slashes. All user external links flagged `rel="ugc nofollow"`. | Search Console & sitemap crawler validation |

## 3. Business Rules Matrix

| Rule Code | Rule Statement | Enforcement Location |
| :--- | :--- | :--- |
| **BR-1** | A project can be published ONLY if it possesses: Title, Summary (≤140 chars), 16:9 Cover Image, ≥1 Technology, and ≥1 Link (Live or Repo). | Client-side checklist & Server-side API validator |
| **BR-2** | Each project has exactly one cover image. | Database schema & R2 storage handler |
| **BR-3** | Maximum of 30 projects per developer account. | Server-side project creation handler |
| **BR-4** | Maximum of 6 featured projects per developer account. | Server-side toggle handler |
| **BR-5** | A project may list up to 15 technologies and up to 5 free-text tags. | Zod validation schema |
| **BR-6** | Profile slugs are immutable once generated from initial GitHub login. | Database constraint & Settings UI |
| **BR-7** | Reserved system slugs (`admin`, `api`, `login`, `dashboard`, `settings`, `about`, `faq`, `terms`, `privacy`, `sitemap`, `robots`) are blocked. | Zod validation & slug generator |
| **BR-8** | External URLs must use `http` or `https` protocol and be normalized without trailing slashes. | Zod URL transformer |
| **BR-9** | A developer profile with 0 published projects is excluded from `sitemap.xml` and served with `noindex`. | Server-side metadata generator |

## 4. Data Requirements

### Entity Relationship Mapping
- **`User` (Better Auth base + Showphan extensions):**
  - `id`: String (UUID/CUID)
  - `github_id`: BigInt / String (Unique)
  - `slug`: String (Unique, immutable)
  - `display_name`: String
  - `bio`: String (Max 160 chars)
  - `avatar_url`: String
  - `search_visible`: Boolean (Default: true)
  - `created_at`: DateTime
- **`Project`:**
  - `id`: String (UUID/CUID)
  - `user_id`: String (Foreign Key -> User.id, Cascade Delete)
  - `slug`: String (Unique per user scope)
  - `title`: String
  - `summary`: String (Max 140 chars)
  - `description`: String (Markdown text)
  - `cover_image_key`: String (R2 object key)
  - `live_url`: String (Optional)
  - `repo_url`: String (Optional)
  - `role`: String (Optional)
  - `learnings`: String (Optional)
  - `tags`: String[] (Max 5 items)
  - `status`: Enum (`DRAFT`, `PUBLISHED`)
  - `is_featured`: Boolean (Default: false)
  - `position`: Integer (Order sequence)
  - `created_at`: DateTime
  - `updated_at`: DateTime
- **`Technology`:**
  - `id`: String (UUID)
  - `name`: String (Unique)
  - `slug`: String (Unique)
  - `icon_color`: String (Iconify key)
  - `icon_mono`: String (Iconify key)
- **`ProjectTechnology`:**
  - `project_id`: String (Foreign Key -> Project.id, Cascade Delete)
  - `technology_id`: String (Foreign Key -> Technology.id)

## 5. Constraints & Out of Scope

### Constraints
1. **Zero-Budget Hosting:** Must operate strictly within free tier quotas of Vercel (Hobby), Neon (0.5GB compute-idle), and Cloudflare R2 (10GB / 1M writes).
2. **Single Identity Provider:** Authentication restricted strictly to GitHub.
3. **No Embedded Demos:** Security and performance isolate Showphan from running untrusted third-party iframe code.

### Refined Out of Scope (Version 1)
- Resume / CV export.
- Social feeds, comments, likes, or upvotes.
- Multi-user platform search.
- GitLab / Bitbucket / Google OAuth logins.
- Automatic website screenshot capture service.
- Paid plans or monetization features.
